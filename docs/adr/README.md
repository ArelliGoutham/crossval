# Architecture decision records

Create an ADR for a durable decision that affects more than one module, changes a public contract, or would be costly to reverse.

Use sequential names such as `0001-nextjs-modular-monolith.md`.

Each ADR should include:

1. Context and the decision to make.
2. Considered options and trade-offs.
3. The decision and its rationale.
4. Consequences, including constraints introduced by the choice.
5. Any superseded decision.

Do not use ADRs for routine implementation details. The first ADR should be written only after the architecture discussion is approved.
